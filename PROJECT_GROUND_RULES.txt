================================================================================
                    AI CUSTOMER SUPPORT PLATFORM - PROJECT GROUND RULES
================================================================================

PROJECT OVERVIEW:
-----------------
This is an AI-powered customer support platform that scrapes websites to create
intelligent chatbots for businesses. The system provides multi-channel support
through WhatsApp, Email, and Web interfaces.

CORE FUNCTIONALITY:
------------------
1. Website Scraping: Automatically extracts product information from e-commerce sites
2. AI Chatbot: Creates intelligent responses using scraped data
3. Multi-Channel Support: WhatsApp, Email, and Web chat integration
4. User Management: Multi-tenant system with user authentication
5. Analytics: Conversation tracking and performance metrics
6. Product Management: CRUD operations for scraped products

GROUND RULES FOR DEVELOPMENT:
============================

1. MODULAR ARCHITECTURE:
   - Every single function must be in its own Python file
   - Each file should contain only ONE primary function or class
   - Related functions can be grouped in the same folder
   - Maximum file size: 200 lines of code

2. DOCUMENTATION REQUIREMENTS:
   - Every file must have extensive comments (minimum 40% comment-to-code ratio)
   - Every function must have detailed docstrings
   - Every variable must have inline comments explaining its purpose
   - Every complex logic block must have explanatory comments
   - Comments should be written for both humans and AI assistants

3. FOLDER STRUCTURE:
   - /functions/ - Core business logic functions
   - /routes/ - Flask route handlers
   - /database/ - Database operations and models
   - /scraper/ - Web scraping functionality
   - /ai/ - AI and chatbot related code
   - /integrations/ - Third-party integrations (WhatsApp, Email)
   - /utils/ - Utility functions and helpers
   - /templates/ - HTML templates
   - /static/ - CSS, JS, images
   - /config/ - Configuration files
   - /tests/ - Unit tests
   - /docs/ - Documentation files

4. NAMING CONVENTIONS:
   - Files: snake_case.py (e.g., user_authentication.py)
   - Functions: snake_case (e.g., create_user_account)
   - Classes: PascalCase (e.g., UserManager)
   - Variables: snake_case (e.g., user_id)
   - Constants: UPPER_CASE (e.g., MAX_PRODUCTS)

5. CODE QUALITY STANDARDS:
   - Every function must have error handling
   - Every function must have input validation
   - Every function must return consistent data types
   - Every function must be testable
   - No function should exceed 50 lines of code

6. SECURITY REQUIREMENTS:
   - All user inputs must be validated and sanitized
   - All database queries must use parameterized statements
   - All sensitive data must be encrypted
   - All API endpoints must have authentication
   - All file operations must validate paths

7. PERFORMANCE REQUIREMENTS:
   - Database queries must be optimized
   - Large operations must be paginated
   - Heavy processing must be asynchronous
   - Caching must be implemented where appropriate
   - Memory usage must be monitored

8. TESTING REQUIREMENTS:
   - Every function must have unit tests
   - Every route must have integration tests
   - Every feature must have end-to-end tests
   - Test coverage must be minimum 80%
   - Tests must be automated

9. DEPLOYMENT REQUIREMENTS:
   - Environment-specific configuration files
   - Docker containerization support
   - Database migration scripts
   - Backup and recovery procedures
   - Monitoring and logging setup

10. MAINTENANCE REQUIREMENTS:
    - Regular dependency updates
    - Security vulnerability scanning
    - Performance monitoring
    - Error tracking and alerting
    - Documentation updates

TECHNOLOGY STACK:
================
- Backend: Python Flask
- Database: SQLite (development), PostgreSQL (production)
- AI: Groq API for language processing
- Scraping: BeautifulSoup, Selenium
- Integrations: Twilio (WhatsApp), SMTP (Email)
- Frontend: HTML, CSS, JavaScript, Bootstrap
- Deployment: Docker, Nginx

DEVELOPMENT WORKFLOW:
====================
1. Create feature branch from main
2. Write function with extensive comments
3. Create unit tests for the function
4. Update documentation
5. Submit pull request with detailed description
6. Code review focusing on comments and structure
7. Merge after approval and testing
